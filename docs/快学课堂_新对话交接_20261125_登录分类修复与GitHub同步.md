## 最新两项故障修复

### 登录视频与上下留白

用户在安装后的正式客户端看到视频停留在海报画面，右侧上下为纯黑区域。

正式登录页的 CSP 包含 `media-src 'self' blob: https:`。旧客户端注入 `data:video/mp4`，会被该策略阻止。之前的本地测试页面缺少这项正式策略，漏掉了此场景。

现有实现将随包视频的 Base64 解码成 Blob，再创建 Blob URL。登录视图显式允许自动播放，视频保持静音循环。视图恢复可见时会尝试继续播放，并在页面退出时处理 Blob URL 生命周期。

上下区域以同一素材的海报作为柔化背景，使用 24 秒缓慢位移动效。主视频仍保持 `object-fit: contain`。减少动态效果偏好会关闭背景位移动效，窄屏沿用原有单列登录布局。

- `src/ui/LoginMedia.jsx`
- `src/ui/login.css`

### 正式课程无法读取

本轮最近一次正式接口联测得到以下结果。

- `/api/v1/catalog/courses` 返回 200，包含两门正式课程。
- `/api/v1/catalog/categories` 返回 404，该响应缺少桌面来源所需的 CORS 响应头。
- 课程封面与已抽查的课程详情返回 200。

旧客户端由渲染进程直接读取分类接口。浏览器将这次请求判为跨域失败，代码无法获得 HTTP 404 状态，继而把整个课程目录置为失败。

现有实现新增受信任窗口限定的 `catalog:categories` IPC。主进程只读取正式配置中的分类接口，保留 HTTP 状态和 JSON 正文，渲染进程据此执行兼容处理。

- 200 响应按 `data.entries` 展示后台配置。
- 404 响应采用旧服务兼容逻辑，保留嵌入式配置或默认的画布课程、VibeCoding 入口。
- 其他错误继续进入现有错误处理，取消请求仍保留取消语义。

## 分类对接约定

客户端正式请求基址为 `https://aicyld.com.cn`，分类路径为 `/api/v1/catalog/categories`。

主站候选服务的公开响应格式如下。

```json
{
  "data": {
    "categories": ["创作实训", "视觉设计"],
    "entries": [
      {
        "id": "canvas",
        "label": "画布课程",
        "filterType": "mode",
        "filterValue": "CANVAS",
        "enabled": true
      },
      {
        "id": "visual_design",
        "label": "视觉设计",
        "filterType": "category",
        "filterValue": "视觉设计",
        "enabled": true
      }
    ]
  }
}
```

- `entries` 数组顺序即入口顺序。
- `filterType` 支持 `mode` 和 `category`。
- 模式值为 `CANVAS` 或 `VIBECODING`。
- 客户端保留固定的全部课程入口，并跳过停用项。
- 成功返回的空入口数组会使客户端仅显示全部课程。
- 新接口解析器支持后台最多 30 个入口和带下划线的入口 ID。
- 桌面端以 `null` 表示全部课程，已经处理后台入口 ID 为 `all` 的冲突。
- 客户端刷新目录会重新读取配置，分类调整生效后可直接刷新使用。

### 两套服务端配置的实际差异

`E:\快学课堂` 中独立开发服务使用 `kx_catalog_settings`、`catalogCategories()`、`saveCatalogCategories()`，其配置是 `{ revision, items }`。此处的旧管理校验器有 20 项限制及更严格的 ID 规则。

主站候选服务使用 `kx_catalog_config`、`catalogConfig()`、`updateCatalogConfig()`，其配置是 `{ categories, entries }`。主站后台和课程分类下拉框已经围绕这套实现完成了工作。

桌面端通过公开接口适配两边。主站发布应以主站候选工程和实际生产课程库为基准，合并时逐项核对配置表和接口，保留已完成的后台工作。
