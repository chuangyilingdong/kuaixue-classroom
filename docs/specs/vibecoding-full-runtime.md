# 快学 VibeCoding 完整运行时规格

## 目标

快学课堂出售的 VibeCoding 工作区必须具备灵动客户端同等的创作能力，不以“能连接工作台”为验收终点。正式放量前，课程运行端必须与随快学发布的灵动客户端版本一致，并随包提供官方技能、插件、浏览器自动化、文档处理和画布素材持久化能力。

## 能力所有者

- 快学课堂负责桌面壳、课程入口、课程版本校验、画布交互、VibeCoding 运行票据和运行镜像。
- 主站负责用户身份、钱包、购课权益、模型计费、课程编排和画布素材的鉴权与对象存储。
- 灵动运行端负责原版 ZCode CLI、Agent、SKILL、插件、MCP 和工程文件服务。
- 主站对象存储负责画布素材的持久化；快学不得把浏览器内存中的临时 URL 当作作品数据。

## 运行版本约束

- 课程运行镜像内的 ZCode CLI、服务协议和随包 `packages/` 必须来自同一版本基线。
- 正式发布时记录 CLI 版本、插件清单、技能清单和镜像摘要；版本不一致时构建失败。
- Browser Use 使用 CLI 管理的 headless Chromium（`cdp` 后端）。镜像内必须具备 Chromium 和运行依赖。
- 官方插件默认随运行时安装。桌面专属且无法在无桌面容器工作的插件必须明确禁用并记录原因。

## 浏览器能力

- Agent 可以自行打开网页、读取 DOM、点击、输入、截图并验证页面。
- 用户点击聊天中的 HTML 作品卡片时，必须直接看到作品，不依赖桌面 IAB 或用户安装浏览器。
- 单文件 HTML、工程内相对 JS/CSS/图片和外部 HTTP(S) 页面分别有明确支持边界。
- 执行学员 HTML 的预览必须与课程 RPC 凭据隔离，禁止获得宿主文件系统、Cookie 或工作区 RPC 权限。

## 画布素材

- 学员拖入图片、视频或音频后，先出现上传中的框体，上传成功后同一节点获得持久化地址。
- 上传必须校验登录状态、已购版本和工作区模式，不接受客户端声明的任意用户或课程。
- 素材对象使用内容哈希或不可猜测 ID，保存 MIME、大小、所有者、课程版本和运行编号。
- 画布快照只保存持久化素材地址；刷新、退出客户端和服务重启后仍可显示。
- 单文件大小、允许 MIME 和单课程容量由主站统一限制，并返回可读错误。

## 验收场景

1. 镜像启动后 `skills list` 至少包含 Browser Use、Office/PDF 和插件开发能力；`plugins list` 与随客户端发布的官方清单一致。
2. 隔离模型驱动 `mcp__node_repl__js` 打开测试网页，返回真实标题并产生截图。
3. 两个内置子 Agent 均能派发并返回结果。
4. 学员将三种媒体拖入画布，刷新页面后同名节点和素材均恢复。
5. 删除或撤销课程权益后，素材上传接口拒绝该用户。
6. 作品卡片可打开单文件交互页面和带相对资源的工程页面。
7. 所有验收记录真实环境、版本、构建摘要和失败项；测试替身结果不得写成生产通过。
