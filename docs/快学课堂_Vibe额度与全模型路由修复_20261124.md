# 快学课堂 Vibe 额度与画布全模型路由修复

日期：2026-11-24

## 结论

- Vibe 额度移到输入框底栏，并改为面向学员的剩余次数。
- `used > limit` 只作为诊断信息保留，不再显示成 `83/10`。
- 额度为 0 时发送按钮和回车提交同时禁用，不再发起注定失败的重试。
- Vibe 工作区默认不打开作品预览；点击“HTML 预览”或“预览作品”后才打开右侧面板。
- 画布全部 52 个已发布渠道模型统一使用主站登记的正式模型键作为 RunningHub 执行路径。
- 未登记的新渠道键在报价前失败关闭，不再等到 RunningHub 返回 `1001 Invalid URL`。

本轮没有发送真实模型对话，没有调用 RunningHub 生成，没有修改任何配额数据。

## 画布全模型路由

规则改为：

```text
课程/后台渠道别名
  -> canvasBillingAliases 中的正式 provider model key
  -> RunningHub price-preview 与 /openapi/v2/{providerModelKey}
```

当前 52 个渠道模型全部一一映射，测试确认：

- 报价键与执行键一致；
- 任何渠道别名都不会进入执行 URL；
- 图片、视频、音频和音乐模型按模型族清理课程内部字段；
- H3 不发送 `generateAudio`；
- MiniMax H3、Seedance 2.0 Mini、Kling、Wan、Muse、Seedream、GPT Image、Nano Banana、
  悠船、Speech、Mureka 的请求字段按已登记契约转换；
- 未登记的 `rh-*` 渠道键在报价前返回明确配置错误。

## 主站计数恢复

17:49 的“弹弓小英雄”运行在旧客户端中仅发送一次后显示 `10/10`。生产记录显示：

```text
runId = 9657abd4-fdc1-4ab0-908d-71bee81df493
usageLimit = 10
usedCount = 10
query ledger rows = 0
```

证明该运行仍由自动对账回退前的旧实现计数：没有写入用户回合 `query-id` 台账，每次模型请求
都会执行 `usedCount + 1`。一次发送中的工具调用和重连因此把计数推到上限 10。

已将自动对账回退时覆盖的两个主站文件恢复为已验收版本：

```text
/srv/aicyld/main-prod/dist/server/routes/kuaixueRuntime.js
41eead7ce765bdd54e07d460db54ea6da44fe77ab17f408f352bb56cc1cd0b32

/srv/aicyld/main-prod/dist/server/lib/kuaixueRuntimeUsage.js
fdeaabf92939f59f58b3848e62c118394dd3736f30ab7ac8784f8ad136309996
```

恢复后的规则：

- 同一 `runId + x-query-id` 只计一次；
- 工具调用、续写和 ZCode 重连复用同一用户回合的额度；
- 额度耗尽返回 `HTTP 402`，ZCode 不再按 429 进入 10 次重连退避；
- 三个额度响应头继续返回。
