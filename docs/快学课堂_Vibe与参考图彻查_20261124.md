2026-11-24

## VibeCoding：为什么此前仍不可用

课程工作台此前主动关闭了以下能力：

```text
allowOpenWorkspace = false
selectDirectory() = null
selectFile() = null
selectFiles() = []
```

因此界面虽然显示了“打开文件夹”，实际点击不会打开系统目录选择器；
新建工作区入口也会被上游拦截。输入框没有初始焦点，用户首次
进入后可能一直得到“能看见但不能输入”的体验。

本次修复：

1. 课程页与 Vibe iframe 增加受控消息桥，只接受当前 iframe 来源的请求。
2. Electron 主进程提供原生目录和文件选择器。
3. Vibe 恢复打开工作区、切换工作区、创建 scratch workspace 和添加附件所需入口。
4. Vibe 就绪后自动聚焦输入框，不打开完整设置页。
5. 首次载入不再把课程工作区退化成隐藏的 conversation workspace。

本地 Electron 实测：

```text
编辑器可编辑 = true
“打开文件夹”可点击 = true
选择 alternate-workspace 后工作区切换成功 = true
```

## MiniMax-H3：参考图在发出前被全部丢弃

画布传入：

```json
{
  "referenceAssets": [
    {"type": "IMAGE", "url": "https://..."},
    {"type": "IMAGE", "url": "https://..."}
  ]
}
```

旧执行适配器只接受字符串：

```js
input.referenceAssets.filter(item => typeof item === 'string')
```

因此对象数组被过滤成空数组，MiniMax-H3 根本没有收到 `imageUrls`。
上游不会创建有效任务，最终表现为“RunningHub 未返回任务编号”。

本次修复同时处理两件事：

1. 从 `url`、`assetUrl` 或 `previewUrl` 正确提取参考图地址。
2. 对课程服务内受登录保护的素材签发短期公网访问 URL，RunningHub 可读取，
   普通未登录读取仍返回 `401`。

生产验证：

```text
签名素材读取 = 200
未签名素材读取 = 401
错误签名读取 = 403
```
