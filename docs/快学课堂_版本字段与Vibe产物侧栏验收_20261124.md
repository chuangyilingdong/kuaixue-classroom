## Dnins 为什么再次出现解锁

后台发布课程版本时会生成新的 `versionId`。当前权益设计按 `courseId + versionId` 保存，因此新版本不会自动继承旧版本已确认订单。

生产记录：

```text
用户：Dnins
课程：弹弓小英雄 (214e5157-8ad2-45da-9348-12e06710a0ba)
旧版本：f3aec750-e918-4930-b468-794c4abd1ef8
新版本：1b79ee75-b4f1-410f-bcbf-c1c9f1b29e71
```

Dnins 在新版本上的确认订单时间为 `2026-11-24 19:15:07`（Asia/Shanghai）。客户端刷新后已显示“课程工作区”，不再显示解锁按钮。

这不是数据被还原。当前产品约束是版本级权益；如业务要求“购买一次，后续课程版本免费升级”，需要单独变更主站和课程服务权益规则，并处理已经产生的新版本订单。

## 用户工作区隔离

课程工作区按以下三元组派生 SHA-256：

```text
userId + courseId + versionId
```

目录只显示 hash 前 8 位。Dnins 当前版本计算结果是：

```text
2f2c07fbeac34ffb4e91f0fe0842d65ac9c2996e204fe2b0753e3b3320334ed3
```

所以 `弹弓小英雄-2f2c07fb` 正是 Dnins 当前版本的工作区。不同用户或不同课程版本得到不同目录，属于预期隔离；hash 后缀不同不会影响使用。

## 原生侧栏预览

ZCode 原始桌面版的 HTML URL 使用内嵌 Browser/webview 侧栏。课程工作台本身运行在 Web iframe 内，当前设置为 `supportsEmbeddedBrowser=false`，无法直接创建 Electron webview。

课程版继续使用 ZCode 原生 code-viewer 侧栏壳层，HTML 内容以 opaque-origin iframe 渲染。修复点：

- 不再使用在 Chromium 中会崩溃的 `srcDoc` 组合；
- 从 HTML 内容创建 `blob:` URL；
- 保留 `sandbox`，不加入 `allow-same-origin`；
- URL 变化或组件卸载时撤销 blob URL。
