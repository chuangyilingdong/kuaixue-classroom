# 快学课堂 Vibe 与 MiniMax-H3 可恢复修复验收（2026-11-24）

## 结论

本轮修复已完成并在正式账号、生产服务和安装后的客户端上验收：

- 进入 VibeCoding 后，课程项目自动创建为 `测试一下-8d619911`。
- 工作区模型显示为 `deepseek-v4.1-flash`，不再显示渠道键。
- 在自动创建的项目中发送“请只回复：发送测试通过”，真实模型返回“发送测试通过”。
- MiniMax-H3 在当前课程节点真实生成成功，页面显示视频并可播放、下载。
- H3 只创建一条新的上游任务，42 积分只结算一次。

## 已确认根因

1. 课程生成接口原先由 Nginx 使用 120 秒超时，而 H3 实际耗时约 3 分 48 秒。浏览器在任务成功前断线，把成功任务误报为失败。
2. 课程服务在 RunningHub 返回 taskId 后没有持久化。请求重试时仍会再次提交上游，产生重复任务。
3. 旧实现即使 taskId 已创建，只要轮询或传输超时也会释放预扣，导致“上游已生成、课程状态未完成、费用状态不一致”。

## 代码修复

- `/api/v1/generations/` 的生产 Nginx 读写超时改为 600 秒。
- `kx_generation` 增加 `provider_task` 列，并自动迁移现有库。
- RunningHub 返回 taskId 后立即写入课程库。
- 同一 job 在服务进程内复用正在执行的 Promise，避免并发重复提交。
- 重试或服务重启后的请求优先按已存 taskId 续查，不再重复创建上游任务。
- 已创建上游任务后的轮询超时保留 42 积分预扣，等待 taskId 续查结算。
- 仅上游明确 `FAILED`，或任务尚未创建时，才释放预扣。
- 客户端生成请求窗口从 360 秒延长到 540 秒。
- 本地课程 HTML 使用 `Cache-Control: no-store`，避免客户端升级后继续加载旧入口。
