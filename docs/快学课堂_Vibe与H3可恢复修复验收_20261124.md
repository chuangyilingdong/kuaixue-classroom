# 快学课堂 Vibe 与 MiniMax-H3 可恢复修复验收（2026-11-24）

## 结论

本轮修复已完成并在正式账号、生产服务和安装后的客户端上验收：

- 进入 VibeCoding 后，课程项目自动创建为 `测试一下-8d619911`。
- 工作区模型显示为 `deepseek-v4.1-flash`，不再显示渠道键。
- 在自动创建的项目中发送“请只回复：发送测试通过”，真实模型返回“发送测试通过”。
- MiniMax-H3 在当前课程节点真实生成成功，页面显示视频并可播放、下载。
- H3 只创建一条新的上游任务，42 积分只结算一次。

## 已确认根因

1. 课程生成接口原先由 Nginx 使用 120 秒超时，而 H3 实际耗时约 3 分 48 秒。浏览器在任务成功前断线，把成功任务误报为失败。
2. 课程服务在 RunningHub 返回 taskId 后没有持久化。请求重试时仍会再次提交上游，产生重复任务。
3. 旧实现即使 taskId 已创建，只要轮询或传输超时也会释放预扣，导致“上游已生成、课程状态未完成、费用状态不一致”。

## 代码修复

- `/api/v1/generations/` 的生产 Nginx 读写超时改为 600 秒。
- `kx_generation` 增加 `provider_task` 列，并自动迁移现有库。
- RunningHub 返回 taskId 后立即写入课程库。
- 同一 job 在服务进程内复用正在执行的 Promise，避免并发重复提交。
- 重试或服务重启后的请求优先按已存 taskId 续查，不再重复创建上游任务。
- 已创建上游任务后的轮询超时保留 42 积分预扣，等待 taskId 续查结算。
- 仅上游明确 `FAILED`，或任务尚未创建时，才释放预扣。
- 客户端生成请求窗口从 360 秒延长到 540 秒。
- 本地课程 HTML 使用 `Cache-Control: no-store`，避免客户端升级后继续加载旧入口。

### Vibe WebSocket EPIPE 热修复

安装验收后，客户端从已关闭输出管道的诊断终端启动，退出 Vibe 时
WebSocket 关闭日志再次写入 `stderr`，触发 `EPIPE: broken pipe` 并被
Electron 显示为“JavaScript error occurred in the main process”。

根因不是模型或工作区数据损坏，而是诊断启动方式关闭了主进程输出管道。
热修复为：

- Electron 主进程启动前为 `stdout`、`stderr` 安装一次错误监听。
- 终端、开发工具或外部父进程断开时，诊断日志失败不再升级为未捕获异常。
- WebSocket、本地运行时和用户工程继续正常关闭，不再弹出主进程错误框。

验收方式：沿用会关闭输出管道的启动命令启动安装版，进入 VibeCoding
后再返回课程，触发 WebSocket 断开；应用保持运行，页面正常返回课程详情，
不再出现 `EPIPE` 对话框。

## VibeCoding 使用次数按用户发送计一次

### 现象与根因

界面上“重新连接中... N/10”并不表示 WebSocket 断线。主站模型网关日志显示，
同一个用户回合中 ZCode 因工具调用连续请求了 8 次
`/api/kuaixue-runtime/v1/chat/completions`，每次都返回：

```text
429 USAGE_LIMIT_REACHED
本课程版本的 VibeCoding 使用次数已用完
```

旧实现按每个模型 HTTP 请求累加 `usedCount`，因此一次用户发送中的工具轮、
续写和重试都被当成独立发送。ZCode 对 429 又按限流处理并指数退避重试，最终
表现为长时间“重新连接中”。

### 对照灵动 AI

灵动 AI 的正式实现：

```text
E:\灵动ai客户端\packages\services\src\zcode-agent\lingdongQuotaLedger.ts
E:\灵动ai客户端\packages\services\src\zcode-agent\zcodeAgentService.ts
E:\灵动ai客户端\packages\desktop\tests\windows-quota-flow.e2e.mjs
```

该实现不是按模型请求扣次，而是在用户发送命令入队时按
`workspace + sessionId + commandId` 预占一次。同一次发送产生的所有工具调用
复用同一 `commandId`；命令被拒绝或确认重复时才回滚。其 E2E 明确验证：
同一个 sendId 请求 100 次也只记 1 次。

### 快学对应修复

ZCode 的 `x-query-id` 在同一个用户回合的所有模型步骤中保持不变。正式网关现按：

```text
(runId, x-query-id)
```

建立唯一台账，另有 `x-zcode-query-source=main_turn` 用于识别真实用户发送。
同一查询 ID 的工具轮、续写和重试全部复用一次额度；只有新的用户
`x-query-id` 才会增加使用次数。没有该请求头的旧客户端仍按原方式失败关闭。

生产新增表：

```sql
CREATE TABLE IF NOT EXISTS kuaixue_runtime_usage_query (
  id VARCHAR(191) PRIMARY KEY,
  runId VARCHAR(191) NOT NULL,
  queryId VARCHAR(191) NOT NULL,
  querySource VARCHAR(191) NULL,
  createdAt DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY kuaixue_runtime_usage_query_run_query (runId, queryId)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

额度耗尽由 HTTP 429 改为 HTTP 402，并保留错误文本
`本课程版本的 VibeCoding 使用次数已用完`。ZCode 只对 429/5xx 自动重试，
因此 402 会立即显示真实原因，不再进入 10 次重连退避。
