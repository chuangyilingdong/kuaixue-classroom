# 快学课堂课程编排交付 · 2026-11-23

主站负责把新版挂到运营后台现有的「快学课堂 → 课程管理」页面。快学侧已构建页面，并在本机从后台发布、学员端回读，核对了两个连续版本。交付包位于 `E:/快学课堂/release/快学课堂-主站课程编排-20261123.zip`。

## 主站部署

1. 复用现有后台菜单、管理员会话与权限。将包内 `web/course-editor.js`、`web/course-editor.css` 放到后台自己的静态目录，在原页面引入样式，用 `mountCourseEditor(容器元素, 主站已认证的JSON请求函数)` 挂载页面。请求函数接收 `(path, fetchOptions)`，携带主站会话及 CSRF，返回解析过的 `{data}`，遇到 HTTP 错误时抛出服务端错误。前端资源可通过快学仓库 `pnpm build:course-admin` 重新构建。
2. 更新服务端的后台路由、课程版本发布和画布报价逻辑。包中 `integrations`、`apps` 和 `electron` 保留了相互引用的目录结构。若正式服务有独立实现，请对齐下面的接口与版本字段。继续使用当前课程库和审计记录。
3. 给 `mountKuaixueCourses` 注入 `listCanvasModels(actor)`。由主站读取已授权的渠道目录，或转接学院提供的目录。`GET /api/admin/kuaixue/courses/models` 使用 `kuaixue.read`，返回 `{data:[…]}`。以下数据仅展示结构，正式值取自渠道。目录暂缺时，新框体可选择关闭生成，旧课可沿用已发布配置。

```js
{
  id: '<渠道模型 ID>', label: '<运营可见的模型名>', modality: 'IMAGE',
  options: {inputModes: ['TEXT','IMAGE_REFERENCE'], aspectRatios: ['16:9','1:1'],
            resolutions: ['1K','2K'], durations: [], audio: false}
}
```

模型类型支持 `TEXT`、`IMAGE`、`VIDEO`、`AUDIO`，音乐框体对应 `AUDIO`。新开 VibeCoding 的课程通过 `defaultVibeModelIds(actor)` 读取服务端已有的课程模型权限。已有 VibeCoding 课程发布新版时保留原授权。未配置授权时，运行服务继续按其权限检查处理。

主站已有“模型家族·前台显示”映射时，需要在 `mountKuaixueCourses` 注入：

```js
resolveVibeModelLabels(actor, modelIds)
```

返回 `{ [完整模型ID]: 前台显示名称 }`。发布课程时该映射写入 `vibeModelLabels`，课程列表和详情只展示映射名称，`vibeModelIds` 仍保留完整 ID用于运行授权。未提供映射时，客户端只做缩短显示，不能保证与运营配置的名称一致。

## 课程版本和学员工作区

- 画布从 `materialGroups[].materials[]` 读取顺序。`GENERATION_BOX` 的 `snapshot.box` 保存模型、显示名、可选参数及锁定值。`modelBinding: 'BOX'` 表示按框体选择，空模型表示关闭此框体生成。历史课包继续使用原类型策略。新配置的正式模型和参数在发布端按目录复核。
- 画布报价按所购版本和框体节点 `box-<素材ID>` 取服务端模型。固定参数覆盖学员传入值。报价和确认沿用既有网关接口。
- VibeCoding 从同一版本的 `classroomConfig.vibeCoding.presetPrompts` 读取有序的 `{title,text}`，交给课程工作区。
- 快学桌面端须随本次画布适配更新，以显示学生可选参数、音乐模式及关闭生成状态。桌面端源码在快学仓库 `vendor/academy-canvas` 内，由快学侧随客户端发版。

## 部署后核对

从主站后台打开「课程管理」并新建课程，选择画布和 VibeCoding。运营应能在素材组内配置一个生成框体，并在 VibeCoding 栏添加一个按钮和正文。对获准展示的首课核对积分价、两个入口及发布版本，再把正式 `courseId`、`versionId` 交给快学。
