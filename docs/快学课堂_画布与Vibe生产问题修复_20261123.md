# 快学课堂画布与 VibeCoding 生产问题修复

2026-11-23

## 用户反馈

1. 画布生成前出现浏览器确认框，预计积分没有显示在生成按钮旁。
2. 画布仍显示完整渠道模型 ID，AI 图片生成失败。
3. 从课程页进入 VibeCoding 工作区失败。

## 已定位根因

### VibeCoding 无会话

生产日志：

```text
[kuaixue/course-action] start Error: course session unavailable
at attach .../course-models.mjs
```

课程动作先通过 `kuaixue_session` 鉴权，但调用模型宿主时只传了 `userId` 和请求体，没有把原始会话继续传给 `withCourseModels.start()`。模型宿主再次用 `identity(undefined)` 校验时必然失败。

修复：

- `sessionPrincipal()` 保留当前原始会话。
- `handleCourseAction()` 把会话传给平台 `start()`。
- VibeCoding 工作台不再强制要求云端运行票据；没有票据时继续走本机工作区，远端仅在可用时作为内部兜底。

### RunningHub 出站被沙箱拦截

生产日志：

```text
[kuaixue/course-action] generate TypeError: fetch failed
at runningHub .../canvas-generation.mjs
```

`aicyld-kuaixue.service` 配置了：

```text
IPAddressDeny=any
IPAddressAllow=localhost
```

因此回环主站修复后，RunningHub 外网请求仍然失败。使用同一 systemd 限制测得：

- 仅允许回环：连接 `www.runninghub.ai:443` 超时。
- 增加当前 RunningHub AI/CN 地址：请求返回 `200`。

交付 drop-in：

```text
integrations/vibecoding/deploy/aicyld-kuaixue-runninghub-egress.conf
```

该配置只放行 RunningHub 当前解析到的 `/32` 地址，不开放任意公网。CDN 地址变化时必须在发布前重新解析并更新。

## 客户端交互修复

- 删除 `window.confirm` 生成确认框。
- 选中可生成框体后请求只读预览报价，在生成按钮旁显示“预估 N 积分”。
- 点击生成时重新报价并校验余额，余额足够即直接执行。
- 历史画布节点和课程框体都重新规范化模型显示名。
- 常见完整渠道 ID 统一显示为模型家族名，例如 `gpt-image-2.5`。
- 服务端错误优先展示真实原因，不再统一覆盖成“课程服务暂不可用”。
后端执行失败改为可诊断的错误信息，仍不会自动重复生成或重复扣费。
