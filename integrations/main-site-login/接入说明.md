# 快学桌面登录页：主站发布顺序

**微信登录顺序**：先部署主站 `desktop-session?ui=kx-class-v1` 对应的快学扫码回调（只保存结果，不在二维码框跳转首页），再更新 `sign-in/`，先传 `assets/`，最后替换 `index.html`。无需重打客户端。切到「微信」时，未同意不创建会话、不显示二维码、不轮询。勾选后自动出码，取消勾选即收起并停止使用该会话，再勾选生成新码。已绑定账号在手机上确认后直接进入课堂；首次未绑定的微信仍走手机号验证。过期或加载失败可手动刷新。

1. 将包中 `sign-in/` 目录在主站同源 `https://aicyld.com.cn/kuaixue/sign-in/` 挂为静态站点（保留末尾 `/` 与 `assets/`）。不要指向主站 SPA 的兜底页。HTML 用 `Cache-Control: no-store`；启用 `Referrer-Policy: no-referrer`、`frame-ancestors 'none'` 和主站登录页相同的验证码 SDK 策略，允许本站二维码 `img-src data:`。`frame-src` 允许 `https://open.weixin.qq.com`。微信 `desktop-session.qrUrl` 用作内嵌扫码页地址，由微信在电脑上显示可扫码的原码。发布后用手机扫一次，核对手机进入确认页。仅在正式账号域名托管，不能用第三方镜像。
2. 将 `authorize.patch` 的条件分支合入现行课程服务的 `formal-server.cjs`：原有参数校验通过并创建授权事务后，仅新版 `ui=kx-class-v1` 带原 HttpOnly 流程 Cookie 303 到该静态页。没有该参数的旧客户端沿用原流程。原签码、换码、退出接口不变。重载课程服务。先发页面、再发跳转、最后发桌面包。
3. 新页使用主站已有的手机验证码、邮箱密码、微信桌面扫码及人机验证。必须主动勾选协议与权益读取说明；手机号/邮箱提交或微信确认后才调用同源 `POST /kuaixue/desktop/authorize/complete`。主站账号令牌不入 URL、不传入快学 IPC、不在此页写入持久化存储。仅 PKCE 授权码返回客户端。发送短信、微信绑定和正式账号登录请由账号本人验证。
4. 验收：全新桌面会话直接显示 KX 页面；三种方式均无「使用主站登录」及二次「同意并返回」。取消、验证码失败、请求过期可重试；不勾选不签码；成功后进入课堂，退出后不再保留快学权益。已有快学会话可复用。普通主站登录页、AIGC 教程、钱包、购课开关都不改。

回退：先退桌面包，再撤新版跳转；不要停现有签码服务。未开启新版分支的环境不要向用户发新桌面包。
